Which layer broke the deploy?

Reusable GitLab CI components, Azure networking as code, security gates, and a small tool that reads a failed deploy log and says whether the pipeline, the source, Linux, the template, Azure, the network or the app broke it.

A deploy fails at the end of a long pipeline. The error is in a different layer than the place you are looking. This lab reads the first real error, names the layer, and tells you the one thing to check next.

The pipeline

Components, composed four times

Each component declares typed inputs. promote.yml is included once per environment and names its job from the input.

include:
  - local: templates/bicep.yml
    inputs: { stage: validate }
  - local: templates/terraform.yml
    inputs: { stage: validate, module_dir: terraform/modules/vnet }
  - local: templates/scan.yml          # gitleaks + checkov
    inputs: { stage: scan }
  - local: templates/promote.yml
    inputs: { environment: staging, stage: deploy-staging, manual: true }
  - local: templates/promote.yml
    inputs: { environment: prod, stage: deploy-prod, manual: true }

Checked with gitlab-ci-local in CI: the file parses, staging and prod are manual, and bicep-validate, terraform-check, gitleaks, checkov, deploy-dev and deploy-test all pass in their containers. It was not run on a GitLab server.

What each part shows

Real, tested, and where it stops

GitLab CI components

templates/*.yml

Typed inputs, rules, needs, artifacts, environments, resource groups, manual gates. Run with gitlab-ci-local, not a GitLab server. Local include, not a catalog.

Azure networking in Bicep

bicep/

Spoke VNet, deny-all-inbound NSGs, route table to a firewall, private storage behind a private endpoint and private DNS. Lints clean, builds for four environments. Never deployed.

Terraform module

terraform/modules/vnet

Validated inputs, one NSG per subnet that always ends in deny-all, terraform test with a mocked provider. No plan against real Azure.

Compliance as tests

tests/test_invariants.py

Python reads the compiled ARM: every NSG ends in deny-all-inbound, storage is private with TLS 1.2 and no shared keys.

Scan gates

templates/scan.yml

Gitleaks for secrets, Checkov for Bicep and Terraform. Both pass in CI. No SAST or container scan in this repo; see gitops-aks-demo for Trivy.

Deploy triage

src/deploytriage

Eight rules, first failure wins, nested Azure errors preferred over wrappers. Rules, not a model.

GitOps

gitops-aks-demo

CI writes desired state to Git, Argo CD syncs AKS, nothing in CI runs kubectl. A separate personal project, linked not copied.

Decisions and trade-offs

Why this and not that

All design-only: nothing here ran in production.

Components with typed inputs over copied YAML
WhyInputs are checked when the pipeline is created, versions are pinned, policy lives in one place.
CostsSomeone has to maintain them and a one-off change is slower.
Flip whenOne project, no reuse.
Private endpoint over a service endpoint
WhyA private IP inside your VNet and no public path.
CostsPer-endpoint charge and private DNS you must get right.
Flip whenA service endpoint with a firewall rule is enough and cost matters.
Mocked-provider tests over integration tests
WhyFast, free, no credentials.
CostsThey cannot catch provider or API behaviour.
Flip whenThe risk is in the real API; add a sandbox subscription run.
Manual gate on staging and prod over fully automatic
WhyA person approves what reaches production.
CostsThe pipeline can sit blocked.
Flip whenHealth-gated automatic rollback is trusted for that environment.
Rules in the triage tool over a model
WhyPredictable and explainable.
CostsMisses messages it has not seen.
Flip whenThere are enough labelled logs to measure a classifier against the rules.
Checkov and Gitleaks as pipeline gates over a review checklist
WhyEvery merge request gets the same checks.
CostsFalse positives need an exception path.
Flip whenA finding class is too noisy to block on.
